# Ticket Planner v0.2

생각하기 싫을 때 현재 해야 할 행동 하나를 정해 주는 로컬 우선 개인 실행 도구입니다. Next.js App Router, TypeScript, Tailwind CSS를 사용하며 AI API와 서버 DB는 연결하지 않았습니다.

## 실행

Node.js 20.9 이상에서 다음을 실행합니다.

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3040`을 엽니다.

## 현재 기능

- `/`: 첫 지령 발행 → ACTIVE → 완료 또는 실패 → 음원 재생 중 다음 지령 자동 재발급
- `/tasks`: 할 일, 마감, 예상 시간, 중요도, 수행 진행도 관리
- `/schedule`: 실제 일정과 반복 루틴 관리, 반복 없음·매일·매주 지원
- `/settings`: 사용자 설정, 전체 데이터 JSON 백업·복원, 최근 Planner 판단 기록 확인·복사
- 전역 CRT 스캔라인·비네팅, Limbus Beep App의 원본 `beep.wav`, 새 지령 전체의 점진적 텍스트 복호화 연출
- Limbus Beep App의 원본 청색 팔레트를 적용한 검정–파랑 단말기 테마
- 원본 음원이 재생되는 동안 결과 기록과 Planner 재계산, 다음 지령 발행이 함께 진행됩니다.
- 기본 발급음이 끝난 뒤에도 상태 전이가 완료되지 않으면 `limbus-beep-wait-loop.wav`를 반복하고, 발급 성공 또는 실패 즉시 정지합니다.
- 원본 음원 재생이 차단되면 880Hz → 440Hz 하강 사각파를 0.7초 간격으로 세 번 재생합니다.
- 모든 상태는 해당 브라우저의 `localStorage`에 저장됩니다. 브라우저의 Web Locks API가 있으면 탭 간 쓰기도 직렬화합니다.
- Planner는 지령마다 선택·후보·제외 근거를 함께 저장하며, 설정 화면에서 최근 50건을 확인할 수 있습니다.
- 마감 경과, 날짜 변경, 장시간 방치로 오래된 ACTIVE 지령은 자동 삭제하지 않습니다. 계속 수행하거나 `시간 경과` 실패로 남긴 뒤 재계획할 수 있습니다.
- 등록된 실행 후보가 없으면 정리, 물 마시기, 걷기, 휴식, 스트레칭을 처리 이력 순서에 따라 결정론적으로 순환합니다. 이상 지령 신고도 다음 순환 항목으로 넘어갑니다.
- 설정에서 전체 상태를 JSON 파일로 내보내거나 복사할 수 있으며, 선택한 백업은 두 번째 확인 후에만 현재 데이터를 교체합니다.
- 미래 지령을 미리 만들거나 메인 화면에 표시하지 않습니다.
- 스마트폰 가로 화면에서는 지령과 처리 버튼, 달력과 날짜별 목록, 설정과 백업을 나란히 배치합니다. 입력창은 현재 화면 높이와 하단 메뉴 공간을 고려해 내부에서 스크롤하며, 노치·홈 제스처 공간도 확보합니다.
- 지령의 `i` 정보 영역에서 이상 지령을 신고할 수 있습니다. 여섯 가지 사유 중 하나를 선택하면 `INVALID`로 이력을 보존하고 즉시 새 지령을 발행합니다. 사용자 실패 횟수와 Task 수행 진행도에는 반영하지 않습니다.
- 설정의 이상 지령 기록에서 사유별 사례와 발행 당시 판단을 확인·복사할 수 있습니다. 이 피드백은 Planner 규칙을 자동으로 수정하지 않습니다.

## Planner 규칙

Planner는 순수 TypeScript 함수이며 같은 입력에는 같은 결과를 반환합니다.

1. 현재 진행 중인 고정 일정
2. 15분 안에 시작하는 일정 준비
3. 긴급 Task: 마감 경과 또는 3일 이내 마감
4. 현재 시간대의 실행 가능한 Routine
5. 일반 Task
6. System fallback: 정리, 물 마시기, 걷기, 휴식, 스트레칭 순환

Task와 Routine은 서로 점수를 겨루지 않습니다. 같은 Task 계층에서는 마감 구간, 중요도, 마지막 선택 시각, ID 순으로 정렬합니다. 마감 구간은 경과·6시간·24시간·3일·1주·그 이후/마감 없음으로 나누며, 같은 구간 안에서는 정확한 마감 시각보다 중요도가 먼저입니다. 선택 이력이 없는 Task는 동일 마감 구간·중요도의 이미 선택된 Task보다 먼저 옵니다. 마지막 선택 시각은 기존 지령의 발행 이력에서 계산하므로 별도의 Task 필드나 데이터 이전은 필요하지 않습니다.

`getAvailableWindow(now, schedules)`는 다음 고정 일정까지의 시간에서 5분을 뺀 뒤 0~120분으로 제한합니다. Task 수행시간은 남은 작업 시간·30분·공통 가용시간 중 가장 짧은 값이며, 5분 미만이면 제외합니다. Routine도 공통 가용시간과 루틴 종료까지의 시간 안에서 최대 30분을 수행하며, 5분 미만이면 제외합니다. 현재 일정 수행과 임박한 일정 준비는 이 자유시간 필터보다 먼저 처리합니다.

일정 준비가 실패로 보류된 상황에서도 남은 자유시간이 5분 미만이면 새 작업 대신 일정 전 대기를 발행합니다. 대기 이력은 정리·물·걷기·휴식·스트레칭의 순환 횟수를 바꾸지 않습니다.

`time_shortage` 또는 `too_difficult`로 실패한 Task는 다음 발행에서 더 짧은 작업 단위로 조정합니다. 일정 변경·몸 상태는 4시간, 장소·도구 문제·시간 경과는 2시간 동안 해당 항목의 재발행을 보류합니다. 이 보류는 다른 지령을 처리해도 유지되며, 같은 항목을 나중에 완료하면 이전 실패 영향이 끝납니다. 시간 부족에 따른 축소가 가용시간을 늘리지는 않습니다.

발행된 지령과 Planner 기록에는 실제로 선택을 가른 근거를 함께 저장합니다. Task 판단 기록에는 마감 구간·중요도·마지막 선택 시각을 보존하여 백업·복원 후에도 판단을 추적할 수 있습니다. ACTIVE 지령이 이미 있으면 다음 행동을 계산하기 전에 추가 발행을 거부합니다.

## 사용자 결과와 Planner 피드백

`COMPLETED`는 수행 완료, `FAILED`는 유효한 지령을 수행하지 못한 결과, `INVALID`는 현재 상황에 부적절한 지령에 대한 피드백입니다. 중복 ACTIVE 복구용 `CANCELLED`는 그대로 유지하며 이상 지령 신고와 혼용하지 않습니다.

이상 지령은 `invalidReason`, `invalidatedAt`, 원래 판단 기록의 `invalidDecision`으로 보존합니다. `completedAt`·`failureReason`을 사용하지 않아 달력과 메인의 완료·실패 횟수에 포함되지 않습니다. 원래 판단은 최근 50건의 Planner 로그가 정리되어도 피드백 이력 안에 남으며 전체 JSON 백업에 포함됩니다.

Task·Routine·Schedule은 이상 신고 후 30분 동안 원본 `sourceType`과 `sourceId` 기준으로 재발행을 보류합니다. System 행동은 신고도 순환 진행에 포함해 다음 행동으로 이동하며, 직전에 신고한 동일 System 행동은 즉시 재발행하지 않습니다. 짧은 가용시간의 대기 지령도 다른 대기 행동을 선택하여 즉시 반복을 피합니다.

Task 지령을 완료하면 `completedMinutes`가 증가하고 예상 시간을 채우면 자동으로 `DONE`이 됩니다.

## Android 알림음

지령 확인·루틴 시작 알림은 제공된 `sound_3x_0.5s_gap_fixed (1).wav`를 원본 그대로 사용합니다. 음원은 `android/app/src/main/res/raw/directive_alert.wav`로 포함되며, 앱 안의 지령 출력음과는 별개입니다.

기존 설치의 채널 소리가 유지되는 문제를 피하기 위해 `directive-alerts-custom-v1` 새 알림 채널을 사용합니다. APK를 새로 빌드·설치한 뒤 앱을 한 번 열면 새 채널 생성과 향후 예약 알림 교체가 진행됩니다. 시스템 무음·방해금지와 사용자가 선택한 새 채널 설정이 우선합니다. iOS에도 같은 WAV를 앱 번들에 포함하고 개별 알림 sound로 지정합니다.

## Android 캘린더 등록 위젯

Android 홈 화면의 위젯 목록에서 **지령 단말기 → 할 일 등록 달력**을 선택합니다. 기존 활성 지령 표시 위젯은 그대로 유지됩니다.

- 검정·파랑 월간 달력, 오늘 강조, 날짜별 미완료 할 일 수를 표시합니다.
- 날짜를 누르면 앱이 열리며 해당 날짜의 새 할 일 등록창으로 바로 연결됩니다.
- 이전·다음 달 이동, 현재 달로 돌아가는 `오늘`, `+ 오늘 등록`을 지원합니다.
- 여러 위젯의 표시 월은 독립적이며 가로·세로 크기를 조절할 수 있습니다.
- 등록·수정·삭제·완료·데이터 복원 후 앱에서 위젯 표시를 갱신합니다. 등록과 중복 시간 검사는 기존 앱 로직을 이용합니다.

원본 데이터는 앱의 localStorage에 그대로 저장하며 Android SharedPreferences에는 날짜별 개수만 표시용으로 복사합니다. 외부 캘린더 권한·계정·서버는 필요하지 않습니다. 이 위젯은 Android 홈 화면용이며 일반 웹 브라우저에는 표시되지 않습니다. 기기 시간대를 바꿨다면 앱을 한 번 열어 개수의 날짜 기준을 갱신합니다.

설계는 `docs/plans/calendarRegistrationWidget.md`에 기록되어 있습니다. 이 위젯은 Android 전용이며 iOS에 WidgetKit 확장을 새로 구현하지 않았습니다.

## 모바일 빌드

Android는 `npm run android:apk`로 디버그 APK를 생성합니다. Windows Java 21에서 Unix-domain pipe 연결 오류가 발생하는 환경의 빌드 우회 방법은 `docs/plans/mobileBuild.md`에 기록했습니다.

iOS 프로젝트는 `ios/App/App.xcodeproj`에 있습니다. Mac에서 의존성을 설치한 뒤 다음을 실행합니다.

```bash
npm ci
npm run ios:sync
npm run ios:open
```

Xcode에서 Signing & Capabilities의 Team과 대상 기기를 선택하고 빌드합니다. Windows에서는 Xcode 빌드·서명·IPA 생성이 불가능합니다. 생성된 iOS 프로젝트는 Mac 빌드 전 단계이며 네이티브 빌드 성공을 의미하지 않습니다.

Mac이 없어도 `.github/workflows/iosBuild.yml`을 GitHub Actions에서 수동 실행하면 `macos-26`과 Xcode 26으로 iOS 빌드를 수행할 수 있습니다. `simulator`는 Apple 계정 없이 시뮬레이터용 앱 ZIP을 만들고, `signedIpa`는 Apple 인증서와 프로비저닝 프로파일을 Repository Secrets로 제공했을 때 실제 기기 배포용 IPA를 만듭니다. 필요한 Secrets와 실행 방식은 `docs/plans/githubActionsIosBuild.md`에 기록했습니다. 서명 없는 결과를 IPA로 포장해도 iPhone에는 설치할 수 없으므로 두 결과를 구분합니다.
