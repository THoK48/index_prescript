# 사용자 지정 알림음

## 목적과 범위

사용자가 제공한 `sound_3x_0.5s_gap_fixed (1).wav`를 Android 지령 확인·루틴 시작 알림에 사용한다. 기기 기본 알림음과 구분하며, 파일 내부의 세 번 비프 및 0.5초 간격을 수정하거나 추가 반복하지 않는다.

## 제외

앱 내부 지령 출력음, Planner, 위젯, 알림 시각·권한 정책, iOS 사운드 번들은 변경하지 않는다. 무음·방해금지 등 OS 정책을 우회하지 않는다. 기존 알림 채널을 삭제하거나 사용자 기기 설정을 강제로 수정하지 않는다.

## 입력·의존성

원본: `C:/Users/Toonation/Downloads/sound_3x_0.5s_gap_fixed (1).wav`.
대상: 독립 Next.js/Capacitor 프로젝트 `outputs/directive-terminal`.
기존 Capacitor LocalNotifications의 Channel.sound 및 LocalNotificationSchema.sound 계약을 사용한다. WAV를 변환하지 않고 `android/app/src/main/res/raw/directive_alert.wav`로 포함한다. Android 리소스 파일명은 플랫폼 제약에 따라 소문자·밑줄을 사용하고 TypeScript 코드는 camelCase로 작성한다.

## 단계

1. 공통 알림음 파일명·채널 정책과 TSDoc을 분리한다.
2. 원본 음원을 Android raw 리소스에 복사한다.
3. Android 8 이상은 `directive-alerts-custom-v1` 새 채널에 알림음을 지정한다. 기존 `directive-alerts`는 삭제하지 않는다.
4. 지령·루틴 알림 모두 새 채널을 사용하며 이전 Android를 위한 개별 sound도 지정한다. Capacitor 기본 알림음 설정에도 같은 파일을 지정한다.
5. 기존 예약 알림 교체 흐름으로 앱 로드 시 향후 알림을 새 설정으로 다시 예약한다.
6. 정책 테스트 소스·문서를 추가하고 비교용 프로젝트 및 소스 ZIP에 반영한다.

## 추후 확인 목록

- 새 설치·기존 설치 갱신 뒤 지령 확인과 루틴 시작 모두 원본 음원을 사용하는가.
- raw 리소스가 빌드 결과에 포함되고 파일명이 채널 설정과 일치하는가.
- 앱 안의 지령 출력음과 Planner 동작이 유지되는가.
- 시스템 무음·방해금지·현재 채널 설정을 존중하는가.

## 위험·대응

Android는 생성한 채널의 소리를 앱에서 다시 지정해도 변경하지 않을 수 있으므로 새로운 채널 ID를 사용한다. 다음에 음원을 변경할 때에도 채널 ID 버전을 증가시킨다. 기존 설치에서는 APK 업데이트 후 앱을 한 번 열어 새 채널 생성 및 예약 교체가 필요하다. 사용자가 새 채널의 소리를 기기 설정에서 바꾸면 OS 설정이 우선한다.

## 복구

이전 채널과 기본 소리를 사용하는 소스로 복구할 수 있다. Task·Routine·수행 기록·저장 키는 변경하지 않는다. 음원의 다운로드 원본도 유지한다.

## 진행·인계

기존 승인 없이 구현 요청을 유지한다. 테스트 소스는 추가하지만 기존 검증 생략 요청에 따라 테스트·타입 검사·빌드·브라우저 확인·APK 재생성은 실행하지 않는다. 기존 APK는 갱신되지 않으며 다음 APK 빌드·설치 후 적용된다.
