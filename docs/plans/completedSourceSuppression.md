# 완료된 Task/Schedule 재발행 방지

## 1. 배경과 목표

소요시간 미지정 Task의 완료가 DOING으로 남고, Schedule 후보가 완료 이력을 확인하지 않아 같은 원본 행동이 재발행된다. 원본 상태와 완료 이력을 후보 생성 단계에서 확인한다.

## 2. 제외 사항

Routine 선택 정책, UI·음원·폰트, AI, 저장소 교체, APK 빌드와 커밋·푸시는 변경하지 않는다. 기존 사용자 방침대로 테스트·타입 검사·빌드·브라우저 검증은 실행하지 않는다.

## 3. 범위

Task 완료·부분 진행 구분, 일회성 일정 완료, 반복 일정의 시작 시각별 회차 식별, 준비와 실제 일정의 분리, 저장/백업 호환 복구, 재계획에 사용하는 완료 후보 제외를 다룬다.

## 4. 입력과 의존성

기존 순수 TypeScript Planner·상태 머신·캘린더 전개 함수·localStorage를 사용한다. 원본 연결은 sourceType/sourceId이며 반복 일정에는 scheduleOccurrenceStartAt을 추가한다. 모든 새 필드는 선택 사항으로 두어 기존 백업을 읽을 수 있게 한다.

## 5. 구현

1. 완료 판정을 공통 도메인 함수로 분리한다. COMPLETED Ticket 한 건을 모든 Task의 최종 완료로 해석하지 않는다.
2. 예상 시간 없는 Task는 완료 시 DONE, 예상 시간 있는 Task는 누적된 완료 블록이 목표에 도달했을 때 DONE으로 저장한다. 부분 완료 블록은 sourceCompleted=false로 구분한다.
3. 일정의 PREPARATION/EXECUTION과 원래 회차 시작 시각을 Ticket에 보존한다. 일회성 일정은 completedAt, 반복 일정은 completedOccurrenceStarts를 원본에 저장한다.
4. 이전 Ticket은 기존 deadline·createdAt·준비 문구로 회차를 복구한다. 완료 처리 시각의 날짜로 회차를 추정하지 않는다.
5. 완료된 원본과 회차를 후보와 다음 고정 일정 경계에서 제외한다. 준비 완료는 본 일정을 막지 않고 같은 준비 지령만 억제한다.
6. 완료 원본·진행량·Ticket을 먼저 갱신한 상태로 재계획하고 기존 단일 저장 전이로 함께 보존한다. 시각 경과·실패·INVALID는 완료로 보지 않는다.
7. 사용자가 Task를 명시적으로 다시 열면 새 진행 주기를 시작하되 이전 Ticket 이력은 보존한다.
8. 회귀 사례를 추가하되 실행은 생략한다.

## 6. 확인 항목

완료 Task, 예상시간 미지정 Task, 부분 수행, sourceType 충돌, 일회성 일정, 일별·주별 반복의 다음 회차, 자정 경계, 준비 완료, 재실행/백업 복원, 시간 경과만으로 미완료 유지, 단일 ACTIVE를 회귀 사례로 남긴다. 실행 결과를 통과한 것으로 보고하지 않는다.

## 7. 복구

기존 원본과 Ticket을 삭제하지 않는다. 새 선택 필드를 무시하는 이전 버전도 백업 구조를 읽을 수 있다. 변경 파일을 되돌리면 이전 정책으로 복구할 수 있으나 재발행 문제도 되돌아온다.

## 8. 위험과 대응

실행 블록 완료와 Task 전체 완료를 분리하며, 날짜는 완료 버튼 시각이 아닌 일정 회차 시작으로 고정한다. 원본과 Ticket의 완료 정보가 다르면 보존된 이력으로 복구하되 명시적인 Task 재개 시각 이전 이력은 새 진행에 합산하지 않는다. 반복 일정의 완료 날짜는 다른 날짜를 차단하지 않는다.

## 9. 인계

소스 수정과 회귀 사례만 제공한다. 설치된 APK에는 이후 빌드가 필요하다. 실제 앱 저장 데이터에 대한 수동 조작·삭제는 수행하지 않는다.
