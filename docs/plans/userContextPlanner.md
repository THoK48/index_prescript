# 사용자 상태 기반 실행 가능성

## 1. 배경과 목표

사용자가 승인한 개선안을 구현한다. 현재 상황을 후보 생성에 반영하되 단일 ACTIVE, 결정론적 Planner, 기존 완료·실패·무효 이력과 CRT 화면을 유지한다.

## 2. 제외

AI·서버·외부 DB·백그라운드 Planner·자동 완료/실패·APK 생성·커밋/푸시는 추가하지 않는다. 기존 요청에 따라 테스트·타입 검사·빌드·브라우저/기기 검증은 실행하지 않는다.

## 3. 범위

활동·몸 상태·명시적 수행 제한 입력, 독립적인 ISO 만료 시각, 모든 종류 후보의 공통 필터, 정상 DEFERRED 결과, 상황 변경 취소, 확인 후 원자적 재계획, 복귀/만료 시 상태 및 알림 동기화와 판단 기록을 다룬다.

## 4. 모델과 의존성

기존 localStorage AppState에 UserContext와 선택적 발행 보류 기록을 추가한다. 이전 데이터는 NORMAL 기본값으로 읽는다. Task/Schedule/Routine/상세 단계/fallback에는 선택적 실행 제약을 둔다. 카테고리나 제목으로 장소·실행 불가능 여부를 추측하지 않는다.

## 5. 작업 순서

1. 순수 상태 정규화·만료·제약 판정과 편집 UI를 추가한다. 활동·피로·제한은 각자 만료되며 현재 시각을 인자로 받는다.
2. 모든 후보에 제약을 적용하고 지속형 작업 단위만 피곤함 15분/몸 상태 나쁨 10분으로 제한한다. 무리한 강도로 명시한 행동은 몸 상태가 좋지 않을 때 제외한다. 이동·완료형 행동을 가짜로 단축하지 않는다.
3. UNAVAILABLE 또는 모든 설정 fallback이 상황상 불가능하면 DEFERRED를 반환한다. 임의 대기 지령으로 ACTIVE를 채우지 않는다. 기존 호출부를 정상 보류 처리로 갱신한다.
4. 작은 현재 상태 버튼과 상태 편집 모달을 추가한다. 저장은 기존 ACTIVE를 보존한다. 충돌 시 별도 확인 뒤 CANCELLED/CONTEXT_CHANGED와 새 발행 또는 보류를 한 번에 저장한다. 오래된 확인은 다른 ACTIVE에 적용하지 않는다.
5. 기존 ACTIVE의 충돌 안내, 발행 보류 이유, 만료 후 재평가를 제공한다. focus/pageshow/visibility 복귀는 저장 상태를 다시 읽고 만료 및 예약 알림을 동기화한다. 유효한 ACTIVE는 교체하지 않는다.
6. 판단 당시 상태·제외 사유·시간 조정 전후를 보존한다. 백업/이전 데이터 파서와 회귀 테스트 소스를 갱신한다.

## 6. 회귀 사례

독립 만료 경계, 잘못된 저장 데이터, 장소 미지정 후보 허용, 명시 제약 필터, 고정 일정/준비/상세 단계/fallback 필터, 피로 시 지속형 축소, UNAVAILABLE 보류, 상태 저장 시 ACTIVE 보존, 취소 시 수행 수 불변, 오래된 확인 충돌, 보류 중 완료 후 저장, 복원 및 만료 재개를 테스트 코드로 남긴다. 실행은 생략한다.

## 7. 복구

원본 항목과 이력을 삭제하지 않는다. 신규 선택 필드를 무시하는 이전 데이터와 호환되게 한다. 되돌릴 때 새 Planner 결과를 소비하는 전이·UI도 함께 복구한다.

## 8. 위험과 대응

활동과 장소를 동일시하지 않는다. 외출 상태에서 '집 필요'처럼 명시한 제약만 제한한다. 야근은 사용자가 지정한 활동 제한만 적용한다. 백그라운드 상태 만료는 앱 복귀 시 판정하며 정확한 시각의 독립 실행을 약속하지 않는다. 새 지령/보류 결과는 기존 저장 잠금 안에서 처리한다.

## 9. 인계

현재 소스만 수정한다. 기존 APK/배포 ZIP은 자동 갱신하지 않는다. 테스트 및 실제 기기 동작을 통과했다고 보고하지 않는다.

### 반영 내용

- 지령 화면 상단과 설정에서 상태를 입력하며, Task·Routine·상세 단계·fallback 편집기에서 명시적 수행 조건을 설정한다. 고정 Schedule도 같은 모델·필터를 사용하고 기존 가져오기 데이터를 지원한다.
- Planner의 DIRECTIVE/DEFERRED 분기를 모든 실제 발행·완료·실패·무효·상황 변경 취소 경로에서 처리한다. 발행 보류는 Ticket 없이 판단 기록에 보존하며 동일한 보류의 연속 기록은 억제한다.
- 확인된 상황 변경 취소는 CANCELLED/CONTEXT_CHANGED로 보존한다. Task 진행량, 사용자 실패 횟수, Planner 품질 피드백에는 포함하지 않는다.
- 앱 진입·복귀·만료는 최신 저장 상태를 사용하며 기존 ACTIVE를 유지한다. 만료로 실제 새 ACTIVE가 생성된 경우에만 메인 출력음 이벤트를 보내고 발행 보류에는 보내지 않는다.
- 독립 만료, 이전 데이터, 명시적 제약, 모든 후보 종류, 시간 축소·유지, 보류, 확인 취소, 오래된 확인, 백업/복원과 판단 이력 보존을 다루는 회귀 테스트 15개를 추가했다. 실행 검증·타입 검사·빌드·APK 생성은 수행하지 않았다.

### 후속 검증 — 2026-10-15

사용자가 테스트·타입 검사·빌드 검증을 명시적으로 요청하여 이번 실행에 한해 기존 검증 생략 방침을 해제했다.

- `npm test`: 두 번 모두 88개 통과, 실패·취소·건너뜀 0개. 사용자 상태 15개와 완료 항목 재발행 방지 회귀 사례를 포함한다.
- `npm run typecheck`: 두 번 모두 종료 코드 0.
- `npm run build`: 샌드박스 안에서는 Turbopack의 CSS 처리용 Node 자식 프로세스 연결 실패로 중단됐다. 제한 환경 밖에서 동일 명령을 두 번 실행해 모두 종료 코드 0으로 성공했다. 소스나 빌드 설정 변경은 필요하지 않았다.
- `/`, `/tasks`, `/schedule`, `/settings`와 기본 not-found 페이지의 정적 생성이 완료됐다.
- 브라우저·실기기 검증, Capacitor 동기화, APK 재생성, 커밋·푸시는 수행하지 않았다. 이번 결과는 웹 프로덕션 빌드와 자동 테스트 범위다.
