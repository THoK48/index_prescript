# 상세 루틴 지령 표시

## 목적

하나의 Routine 내부에 순서가 있는 행동을 저장하되 메인 화면에는 현재 ACTIVE 지령 하나만 표시한다.

## 데이터와 진행

- Routine은 선택적으로 최대 20개의 `RoutineStep`을 가진다.
- 단계에는 안정적인 ID, 행동 문구, 지속형·완료형·이동형 유형, 예상 시간을 저장한다.
- 원본 루틴·단계·반복 회차가 같은 `COMPLETED` 이력으로 첫 미완료 단계 하나를 선택한다.
- 지속형은 완료된 지령의 수행시간을 누적해 목표 분량을 채워야 다음 단계로 이동한다. 30분 상한·피로·가용시간으로 줄어든 블록은 잔여 분량을 이어 발행한다.
- 완료형·이동형은 수행시간 누적과 별개로 명시적 완료 한 번으로 해당 단계를 마친다.
- 발행 당시 반복 회차 구간을 보존하므로 자정 이후나 늦게 완료를 보고해도 다음 회차의 진행량에 섞이지 않는다. 구형 이력은 발행 시각으로 회차를 복원한다.
- 실패·이상 지령은 완료 단계로 세지 않으며 기존 단계별 재발행 보류 규칙을 적용한다.
- 모든 단계가 완료되면 같은 루틴 구간에서는 더 발행하지 않는다.
- 상세 단계가 없는 기존 Routine은 이전과 같이 한 번만 발행한다.

## 화면

- 메인에는 사용자 호칭, 마감 시각, 현재 행동, 발령 시각, 정보 버튼만 유지한다.
- 상위 루틴명과 `현재 단계/전체 단계`, Planner 선택 근거는 정보 버튼을 연 경우에만 표시한다.
- 다음 단계는 메인과 정보 영역 모두에서 미리 표시하지 않는다.

## 문장

- 지속형은 `N분 동안 …할 것.`으로 생성한다.
- 완료형은 행동만 명령하고 바로 위 시간 줄이 마감 시각을 담당한다.
- 이동형은 `지금 …을/를 시작할 것.`으로 생성한다.
- 기존 Routine 제목은 보수적인 키워드 규칙으로 유형을 추론하고, 상세 단계는 사용자가 유형을 명시한다.

## 불변조건

- ACTIVE 지령은 최대 하나다.
- 상세 단계 메타데이터는 지령 본문에 섞지 않는다.
- 기존 CRT, 복호화, 발급음, 완료·실패 전이는 변경하지 않는다.
- 사용자가 별도로 요청하기 전까지 자동 테스트, typecheck, build는 실행하지 않는다.
