# 기한이 지난 Task의 지령 시간 표시

## 1. 배경과 목표

10월 15일 발행한 지령이 원본 Task 마감인 10월 14일을 '…까지'로 표시한다. 발행 당시 이미 지난 원본 마감과 새 수행 구간의 종료 시각을 구분한다.

## 2. 제외

원본 Task 마감·우선순위·진행량·ACTIVE·저장 키를 변경하지 않는다. 지령 재발행·자동 완료·데이터 수정·APK 생성·커밋/푸시는 하지 않는다.

## 3. 범위

시간 표시를 순수 함수로 분리하고, 발행 당시 원본 마감이 지난 Task에 한해 이번 수행 종료 시각을 표시한다. 원래 마감은 정보 영역에 남긴다.

## 4. 의존성

기존 Ticket.createdAt/expectedMinutes/extendedUntil/deadline과 getTicketExpectedEndAt을 사용한다. 새로운 저장 필드나 데이터 마이그레이션은 필요하지 않다.

## 5. 구현

1. 기존 시간 표현·7~15분 기본 안내·대기 지령·무제한 이스터 에그를 공통 표시 모듈로 옮긴다.
2. Task.deadline이 지령 발행 시각 이하인 경우에만 이번 수행 종료 시각으로 표시한다. 계속 수행 연장도 반영한다.
3. 미래 마감·Schedule·Routine은 기존 시각을 유지한다. 오래된 ACTIVE를 현재 시각 기준으로 계속 미래로 미루지 않는다.
4. 정보 버튼 안에 원래 Task 마감과 기한 경과 표시를 추가한다.
5. 날짜·자정·연장·기존 표시 보존 회귀 사례를 추가한다.

## 6. 확인

직전 검증 요청에 이어 이번 수정의 테스트·타입 검사·웹 빌드를 확인한다. 실제 저장 데이터에는 접근하거나 덮어쓰지 않는다. 실기기·APK 검증은 별도다.

## 7. 복구

표시 모듈과 페이지 연결만 이전으로 되돌릴 수 있다. 원본과 지령 이력은 그대로 유지된다.

## 8. 위험과 대응

실제 Task 마감이 연장된 것으로 오해하지 않게 원래 마감을 정보 영역에 보존한다. 현재 시각 대신 고정된 발행 시각을 기준으로 판정하여 지난 ACTIVE의 만료를 숨기지 않는다.

## 9. 인계

개발 서버 소스에 반영되며 기존 ACTIVE도 데이터 변경 없이 새 표시를 사용한다. 배포 APK는 별도 재빌드가 필요하다.

### 검증 결과

- 신규 회귀 사례 5개를 포함한 `npm test` 93개가 두 번 모두 통과했고 별도 `npm run typecheck`도 두 번 성공했다.
- `npm run build`도 두 번 모두 TypeScript 컴파일과 전체 정적 페이지 생성을 완료했다. 기존에 확인한 Turbopack CSS 자식 프로세스 샌드박스 제약을 피하여 일반 환경에서 실행했다.
- 원본 마감이 10월 14일 10:56이고 발행이 10월 15일 17:25인 30분 지령의 표시 종료는 10월 15일 17:55로 검증했다. 자정 경계·연장·미래 마감·오래된 ACTIVE·기본 안내와 이스터 에그 보존도 통과했다.
- 실제 사용자 저장 데이터 수정, 실기기 검증, APK 재생성은 수행하지 않았다.
