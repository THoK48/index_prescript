# 캘린더 등록 위젯

## 목적과 맥락

Android 홈 화면에 검정·파랑 월간 달력 위젯을 추가한다. 날짜를 누르면 앱의 해당 날짜 할 일 등록창으로 연결한다. 기존 ACTIVE 지령 표시 위젯과 Planner는 변경하지 않는다.

## 범위

- 월간 6행 달력, 오늘 강조, 날짜별 미완료 할 일 수.
- 이전·다음 달, 현재 달로 돌아가는 오늘 버튼, 오늘 할 일 등록 버튼.
- 앱 종료 상태와 실행 중 상태 모두 날짜 선택 및 등록창 진입 지원.
- 등록·수정·삭제·완료·백업 복원 후 표시용 네이티브 캐시 갱신.
- 등록은 기존 앱의 저장 계층을 이용하며 동일 시각 중복 방지 정책을 유지한다.

## 제외

위젯 내부 입력 폼, Google Calendar 연동, Android 캘린더 권한, iOS 위젯, 새 저장 DB, Planner 변경은 포함하지 않는다. 위젯은 웹 브라우저 화면 안의 패널이 아니라 Android 홈 화면용이다.

## 입력과 의존성

대상은 독립 Next.js/Capacitor 프로젝트 `outputs/directive-terminal`이다. Toonation 마이크로서비스·shared 패키지를 도입하지 않는다. 기존 Tailwind 등록창과 단말기 테마를 재사용한다. Android RemoteViews 리소스는 Android 파일명 규약을 따르고 새 TypeScript 파일·함수·변수는 camelCase를 사용한다. 신규 함수에는 TSDoc/JavaDoc을 남긴다.

## 단계

1. 순수 TypeScript에 위젯 데이터 투영과 등록 요청 날짜 검증을 분리한다.
2. CalendarWidgetPlugin, CalendarWidgetProvider와 RemoteViews 달력을 추가한다. 각 위젯의 표시 월을 독립 보관하고 PendingIntent의 날짜 충돌을 방지한다.
3. 앱 공통 진입점에서 네이티브 등록 요청을 수신하고 `/tasks/`의 날짜 지정 등록창으로 전달한다. 요청 ID로 중복 전달과 오래된 요청 소비를 막는다.
4. 기존 상태 변경 시 네이티브 표시용 캐시를 갱신한다. localStorage가 원본이며 네이티브 캐시는 읽기 전용 투영이다.
5. 날짜 경계·완료 항목 제외·잘못된 요청·반복 진입에 대한 테스트 소스를 추가하고 사용법을 정리한다.
6. 비교용 소스와 소스 ZIP에 반영한다. 기존 APK는 변경하지 않는다.

## 확인 목록

- 월·연도 경계와 윤년 날짜를 올바르게 선택한다.
- 날짜 탭과 오늘 추가가 모두 지정 날짜의 새 할 일 창을 연다.
- 콜드 스타트·실행 중 재진입·같은 날짜 재탭을 처리한다.
- 화면 이동 뒤 오래된 요청이 등록창을 다시 열지 않는다.
- 신규 등록·삭제·완료·백업 복원 시 개수가 갱신된다.
- 위젯 여러 개의 표시 월이 서로 영향을 주지 않는다.
- 기존 중복 등록 방지 및 단일 ACTIVE 불변조건을 유지한다.
- 위젯 등록이 Planner 또는 지령 수행 이력을 변경하지 않는다.

## 위험과 대응

Android 런처별 크기 차이는 가로·세로 크기 조절과 여섯 개 고정 행으로 대응한다. 시스템 날짜·시간대 변경 시 날짜 표시를 갱신한다. 표시용 캐시에는 필요한 날짜와 개수만 저장하고 Task 원본을 네이티브에서 수정하지 않는다. 브리지 전달은 요청 ID와 명시적 수신 확인을 사용한다. 위젯 변경을 설치본에 반영하려면 APK 재빌드가 필요하다.

## 복구

새 receiver·plugin·달력 리소스와 앱 진입 연결을 제거하면 기존 지령 위젯과 웹 기능으로 복구할 수 있다. localStorage 원본 데이터와 저장 키는 변경하지 않는다.

## 승인과 검증 상태

사용자가 `승인없이 구현`을 명시했으므로 추가 승인 없이 구현한다. 기존 요청에 따라 테스트·타입 검사·웹 빌드·Android 빌드·브라우저 검증은 실행하지 않는다. 확인 목록은 추후 검증용이며 현재 통과를 주장하지 않는다.
