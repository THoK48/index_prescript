# Android 서명 고정 및 1회 데이터 이전

## 1. 배경과 목표

2026-10-14 GitHub 빌드의 임시 키는 보관되지 않아 해당 설치본에 직접 업데이트할 수 없다. 사용자가 승인한 1회 백업·복원 이전을 지원하고, 이후 로컬과 CI가 동일한 기존 로컬 키를 사용하도록 고정한다.

## 2. 제외 사항

기존 휴대폰 앱 삭제·데이터 초기화·자동 설치는 하지 않는다. Git 커밋·푸시와 이전 키 복원을 가장한 새 키 생성도 하지 않는다.

## 3. 범위

Android debug 서명 고정, 키 손실·교체 시 빌드 차단, 키 이중 보관, GitHub Actions secret 설정과 로컬 workflow 변경, 백업 JSON 붙여넣기·복원 전 건수 미리보기, 신규 APK 생성.

## 4. 입력과 의존성

기존 로컬 `.android/debug.keystore`를 재사용한다. 인증서 SHA-256은 `3ecf3515ec98277005128711c4c305b177982c7f20457056b55506dc3e8d83a2`다. 개인용 debug 키의 기존 alias/password를 유지한다. 저장소는 `THoK48/directive-terminal-apk-build-20261014`다.

## 5. 단계

1. 기존 키를 Git에서 제외한 `android/signing/directiveTerminal.keystore`로 복사하고, 작업 프로젝트 밖 별도 경로에 백업한다.
2. Gradle에서 고정 경로·alias·인증서 지문을 확인하며 키가 없거나 다르면 즉시 실패한다. versionCode는 2로 증가한다.
3. CI가 암호화된 저장소 secret으로 같은 키를 복원하도록 한다. secret이 없으면 새 키를 만들지 않고 중단한다.
4. 기존 파일 복원과 동일한 검증·확정 흐름으로 JSON 붙여넣기 복원을 제공하며, 데이터 건수를 미리 보여준다.
5. 로컬 APK를 빌드하고 패키지·버전·인증서 및 키 백업 동일성을 확인한다.
6. 기존 앱에서 백업을 별도로 저장한 것을 확인한 후에만 사용자가 1회 앱을 교체하고 백업을 가져온다.

## 6. 확인 항목

- [x] 고정 키와 프로젝트 밖 백업이 기존 키와 동일함.
- [x] 키 파일이 Git 추적 대상에서 제외됨.
- [x] 잘못된 키로 빌드할 수 없도록 인증서 확인 적용.
- [x] 로컬 workflow가 고정 키 secret 복원을 사용하도록 변경.
- [ ] GitHub secret 등록: 자동 승인 검토에서 서명 키의 외부 전송을 거절해 미실행.
- [x] 최신 APK 빌드·서명·버전 확인.
- [x] JSON 복원은 미리보기와 별도 확정 이후에만 상태 교체하도록 구현.
- [x] 기존 휴대폰 데이터는 변경하지 않음.
- [ ] 실제 휴대폰의 1회 백업·앱 교체·복원: 사용자 작업 필요.

별도 전체 테스트·타입 검사는 기존 생략 방침을 유지하며, 이번 요청에 필요한 빌드와 서명·백업 확인만 수행한다.

## 7. 복구

키 원본과 10월 14일 APK를 보존한다. 빌드·UI 변경은 해당 파일 diff로 복구할 수 있다. 이미 설치한 고정 키 버전의 업데이트에는 계속 같은 키를 사용해야 한다.

## 8. 위험과 대응

백업 JSON은 클립보드에만 두면 재부팅·자동 만료로 잃을 수 있으므로 파일이나 안전한 메모에도 저장한다. 키는 APK나 소스 ZIP에 포함하지 않으며, CI에는 암호화된 secret으로만 보관한다. workflow 변경은 로컬에서 준비하고 사용자 지시 없이 커밋·푸시하지 않는다. 향후 배포 시 versionCode를 증가시킨다.

## 9. 인계

현재 PC에 연결된 Android 기기는 없다. 실제 백업·앱 교체·복원은 사용자 기기에서 진행해야 하며 완료로 간주하지 않는다. 키 보관 위치·GitHub 설정 결과·APK 경로는 작업 후 기록한다.

- 로컬 workflow와 서명 변경은 아직 커밋·푸시하지 않았다. 원격 CI에 적용하려면 키 전송 승인과 커밋·푸시 승인이 필요하다.

### 휴대폰에서 한 번만 진행할 이전 순서

1. 기존 10월 14일 앱의 설정 → 백업 및 복원 → 파일로 내보내기를 실행하고, 파일 앱에서 실제 JSON 파일이 저장됐는지 확인한다.
2. 파일 저장이 되지 않으면 백업 JSON 복사를 사용하고 전체 내용을 별도 메모나 파일에도 저장한다. 클립보드만 남긴 상태로 앱을 삭제하지 않는다.
3. 백업 저장을 확인한 뒤에만 기존 앱을 제거하고 새 APK를 설치한다.
4. 새 앱 설정에서 백업 파일을 선택하거나 복사한 백업 JSON으로 복원을 펼쳐 붙여넣는다. 할 일·루틴·일정·지령 이력 개수를 확인한 뒤 이 데이터로 교체를 누른다.
5. 복원된 내용을 직접 확인할 때까지 백업을 보존한다. 이후 이 고정 키로 서명한 동일 패키지의 업데이트는 삭제 없이 설치할 수 있다.
